## 1. 方向

台灣租屋透明地圖希望透過**易於使用的搜尋**、**看得懂的統計**與**透明的資料來源**，幫助租屋者了解台灣租屋市場。


> [!IMPORTANT]
> **原則：** 每一項租金統計，都必須附上足夠的背景資訊，讓使用者能正確解讀。
>
> **刊登租金（廣告開價）不得被呈現為實際成交租金。**

### 開發原則

本專案採用分階段開發方式，每個開發階段都會產出一個 MVP。每個 MVP 都必須滿足該階段所規劃的使用者故事（User Stories or US）及其驗收條件。

各階段的開發範圍與交付目標請參考 [6](#6-mvp-範圍)。

## 2. Epic A — 查詢租屋資訊

### US-01：依縣市搜尋

**優先順序：** P0

> 身為**租屋者**，我想要**搜尋縣市**，以便**查看我打算居住地區的租屋資訊**。

**驗收條件**

- [ ] 使用者可以輸入縣市名稱。
- [ ] 搜尋可接受常見的寫法差異，例如「台北」與「臺北」、省略「市／縣」。
- [ ] 系統顯示符合的縣市，或清楚的「查無結果」訊息。
- [ ] 選擇縣市後，會開啟該縣市的租屋資訊。
- [ ] 畫面清楚標示目前選擇的縣市。

### US-02：了解資料涵蓋範圍

**優先順序：** P0

> 身為**租屋者**，我想要**知道哪些縣市有租屋資料**，以便**了解平台能在哪些地區提供有用的資訊**。

**驗收條件**

- [ ] 介面標示出有資料的縣市。
- [ ] 每個縣市標示其資料涵蓋的期間。
- [ ] 介面區分以下三種狀態：「有足夠資料」、「資料不足（低於最低樣本數）」、「無資料」。
- [ ] 沒有資料的縣市不會被呈現為有租屋資訊，也不會被解讀為「沒有租屋市場」。
- [ ] 若資料集不完整，介面不會暗示已涵蓋全台。
- [ ] 最低樣本數門檻有明確定義，並且適用於各項統計。

### US-03：查看行政區層級資訊

**優先順序：** P1

> 身為**租屋者**，我想要**依縣市內的行政區查看租屋資訊**，以便**了解不同區域之間的差異**。

**驗收條件**

- [ ] 僅在來源資料支援時才顯示行政區資訊。
- [ ] 每個行政區顯示可用的租金統計。
- [ ] 資料不足的行政區會被明確標示。
- [ ] 使用者可以返回縣市層級總覽。

## 3. Epic B — 理解租屋資訊

### US-04：查看租屋市場摘要

**優先順序：** P0

> 身為**租屋者**，我想要**看到所選縣市的租金摘要**，以便**了解整體租屋行情**。

**驗收條件**

- [ ] 摘要至少顯示一項資料集可支持且有意義的租金統計。
- [ ] 每項統計都標示單位，例如新臺幣／月。
- [ ] 若資料可得，標示租金是否包含管理費、水電等費用；若資料未提供，應明確標示「未提供」或「未知」。
- [ ] 顯示資料期間與樣本數。
- [ ] 提供計算方式說明的連結（見 [US-09：了解統計方法](#us-09了解統計方法)）。
- [ ] 缺漏或不足的資料不會顯示為 0。
- [ ] 統計數字應清楚標示其代表的租金類型。

### US-05：了解租金分布

**優先順序：** P1

> 身為**租屋者**，我想要**看到租金的分布情形**，以便**了解租金的範圍，而不是只依賴單一平均值**。

**驗收條件**

- [ ] 以易懂的圖表或等效方式呈現租金分布。
- [ ] 圖表標示價格區間與單位。
- [ ] 顯示納入計算的資料筆數。
- [ ] 說明計算方式及極端值（離群值）的處理方式。
- [ ] 若樣本數不足以呈現有代表性的分布，應明確提示。

### US-06：了解租金數字代表的意義

**優先順序：** P0

> 身為**租屋者**，我想要**知道這些數字代表的是刊登租金還是實際成交租金**，以便**避免誤解市場資訊**。

**驗收條件**

- [ ] 平台明確標示租金資料的類型（刊登租金／實價登錄成交租金／其他）。
- [ ] 刊登租金不會被描述為實際成交價格。
- [ ] 說明解讀這些數字時的限制，例如資料來源可能偏重特定類型的物件。

## 4. Epic C — 信任與查證資料

### US-07：辨識資料來源

**優先順序：** P0

> 身為**租屋者**，我想要**知道租屋資料的來源**，以便**判斷資料是否可信**。

**驗收條件**

- [ ] 每個資料集都有具名的來源。
- [ ] 若有可用連結，提供來源連結。
- [ ] 平台說明資料是自行蒐集，或取自其他專案／機關。
- [ ] 來源不明或未經查證的資料會被清楚標示。
- [ ] 若有資料授權限制，應記錄並說明其使用範圍。

### US-08：確認資料新舊程度

**優先順序：** P0

> 身為**租屋者**，我想要**知道租屋資料有多新**，以便**判斷它是否反映目前的市場狀況**。

**驗收條件**

- [ ] 若已知，顯示資料蒐集期間。
- [ ] 顯示最近一次更新日期。
- [ ] 平台區分「資料蒐集日期」與「平台更新日期」。
- [ ] 超過定義期限的過期資料會被標示，不會被呈現為最新資料。
- [ ] 資料更新頻率及過期判定標準有文件說明。

### US-09：了解統計方法

**優先順序：** P0

> 身為**租屋者**，我想要**了解租金統計的計算方式**，以便**正確解讀結果**。

**驗收條件**

- [ ] 計算方式有文件說明。
- [ ] 公開樣本數。
- [ ] 說明重要的排除條件與假設。
- [ ] 平台清楚區分中位數、平均數及其他統計量。
- [ ] 公開顯示統計所需的最低樣本數門檻。
- [ ] 若資料經過清理、轉換或排除，應說明相關處理方式。

### US-10：下載租屋資料

**優先順序：** P1

> 身為**租屋者或研究者**，我想要**下載可用的租屋資料**，以便**自行檢視與分析**。

**驗收條件**

- [ ] 在資料授權允許的情況下提供下載。
- [ ] 下載檔案包含來源與日期資訊。
- [ ] 說明檔案格式與欄位定義。
- [ ] 不會洩漏個人資料或其他受限制的資訊。
- [ ] 提供資料使用限制及授權資訊。

## 5. 未來的使用者故事 

以下使用者故事預計在後續開發階段實現。

### US-11：查看租金歷史趨勢

**優先順序：** P2

> 身為**租屋者**，我想要**了解租金隨時間的變化**，以便**掌握較長期的市場趨勢**。

### US-12：比較不同行政區的租屋市場

**優先順序：** P2

> 身為**租屋者**，我想要**比較不同行政區的租金統計**，以便**找出符合預算的區域**。

**優先順序：** P2

> 身為**租屋者**，我想要**依房屋特性（例如套房、雅房、整層住家、坪數）篩選租屋資訊**，以便**查看更具可比性的租屋資料**。

## 6. MVP 範圍

各階段將依照使用者需求、資料可用性及產品發展方向逐步擴充功能，而非一次完成所有功能。

| 開發階段 | 使用者故事 | MVP 交付目標 |
|---|---|---|
| MVP 1 | US-01、US-02、US-04、US-06、US-07、US-08、US-09 | 建立城市租屋資訊搜尋功能，提供租屋市場統計，並確保資料來源、更新時間及統計方法透明。(現階段) |
| MVP 2 | US-03、US-05、US-10 | 提供行政區租屋資訊、租金分布分析及資料下載功能。 |
| MVP 3 | US-11、US-12、US-13 | 提供歷史租金趨勢、行政區比較及租屋資訊篩選功能。 |

## 8. 待釐清問題

以下問題應在產品探索與 MVP 開發階段逐步解決。

### 資料

1. 現有租屋資料集是否足以支撐縣市層級的統計？
2. 資料集代表的是刊登租金、實際成交租金（如內政部實價登錄），還是其他類型的資訊？
3. 資料來源可多久更新一次？
4. 資料授權條款是否允許重新發布與下載？
5. 資料是否包含足夠的縣市、行政區及房屋類型資訊？

### 統計

6. 顯示一項統計之前，最低需要多少樣本數？
7. 資料超過多久應被視為「過期」？
8. 哪些租金統計對租屋者最有用，例如中位數、平均數、每坪租金？
9. 套房、雅房、整層住家的租金差異很大，MVP 是否需要至少依房屋類型分開呈現，以避免混合統計造成誤導？
10. 如何處理異常值、重複資料及缺漏資料？

### 產品與使用者需求

11. 租屋者最希望透過縣市搜尋了解哪些資訊？
12. 縣市層級的統計是否足以協助租屋者做出初步判斷？
13. 是否需要在第一階段就提供不同房屋類型的租金統計？
